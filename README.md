# Экран на ТВ

iOS-приложение показывает экран iPhone в браузере телевизора по Wi-Fi. Одновременно можно подключить два телефона: их экраны встанут рядом.

## Как это устроено

- **Приложение** (`App/`) показывает адрес для телевизора, кнопку запуска вещания и признак того, что вещание идёт.
- **Расширение трансляции** (`Broadcast/`) получает кадры экрана через ReplayKit и раздаёт их по сети:
  - WebSocket на порту 8081 — видео H.264 до 1920 px по ширине, до 60 кадров в секунду, до 12 Мбит/с. Сжимает аппаратный кодировщик телефона. Кадр всегда горизонтальный: декодеры телевизоров LG рассчитаны на 1920×1080 и вертикальное видео 880×1920 не показывают. Портретный экран кладётся набок, а страница поворачивает видео обратно по флагу из заголовка кадра. При повороте телефона разрешение потока не меняется, и плеер не перезапускается;
  - HTTP на порту 8080: `/` — страница для телевизора (`Broadcast/tv.html`), `/stream` — запасной поток MJPEG до 1280 px, `/status` — порты, токен сокетов и адреса других телефонов, найденных через Bonjour, `/log` — журнал диагностики.
- **Страница для телевизора** показывает H.264 через Media Source Extensions с помощью [jmuxer](https://github.com/samirkumardas/jmuxer) (MIT, лежит в `Broadcast/jmuxer.min.js`). Если браузер не умеет H.264 (в том числе слишком старый для jmuxer) или видео не пошло за 8 секунд, страница переключается на MJPEG и через 30 секунд один раз пробует H.264 снова. На подписи телефона видно, какой режим выбран и сколько кадров в секунду пришло по сети («приём») и показано («показ»).
- Страница опрашивает `/status`. Когда появляется второй телефон, она сама подключает его поток и ставит экраны рядом. Если телефон перестаёт отвечать, его экран исчезает через 6 секунд. Если телефон возвращается, экран появляется снова, и H.264 пробуется заново.

Звук не передаётся.

### Подстройка качества

- Если очередь кадров для телевизора переполняется (Wi-Fi не успевает), битрейт снижается в 0,7 раза, но не ниже 3 Мбит/с. Через 15 секунд без заторов он снова растёт в 1,2 раза раз в 10 секунд до 12 Мбит/с.
- Страница раз в 2 секунды сообщает телефону, сколько кадров приняла и показала. Если телевизор трижды подряд показал меньше 80 % принятого, телефон до конца вещания шлёт 30 кадров в секунду вместо 60.
- Принудительный ключевой кадр (для нового зрителя или после затора) — не чаще раза в секунду.

### Защита

Сокет видео принимает только подпротокол `t-<токен>`. Токен создаётся заново при каждом запуске вещания и отдаётся в `/status`. Прочитать ответ `/status` из браузера можно только со страницы, загруженной с телефона в локальной сети (`http://10.x.x.x`, `172.16–31.x.x` или `192.168.x.x`, порт 8080). Поэтому чужой сайт, открытый на ноутбуке в этой же сети, не утащит экран телефона.

Открыть адрес телефона напрямую может любой, кто подключён к той же сети Wi-Fi. Не включай вещание в общественных и гостевых сетях.

### Журнал диагностики

Страница телевизора пишет в журнал на телефоне браузер и его возможности, события сокета, кодек, ошибки плеера, причину перехода на MJPEG и раз в 10 секунд сводку по кадрам. Расширение добавляет туда изменения битрейта и частоты. Прочитать журнал можно с любого компьютера в той же сети: `http://адрес-телефона:8080/log`.

## Сборка

Проект описан в `project.yml` для [XcodeGen](https://github.com/yonaskolb/XcodeGen). Файл `.xcodeproj` в репозиторий не кладётся.

Собирает GitHub Actions (`.github/workflows/build.yml`) на облачной macOS при каждом push. Готовый файл `ScreenShare.ipa` лежит в артефакте `ScreenShare-ipa` на странице запуска (вкладка Actions). IPA собрана без подписи.

Сборка на своём Mac:

```bash
brew install xcodegen
xcodegen generate
open ScreenShare.xcodeproj
```

## Установка на iPhone с Windows

1. Установи iTunes и iCloud с сайта Apple, не из Microsoft Store: Sideloadly нужны их драйверы.
2. Установи [Sideloadly](https://sideloadly.io).
3. Подключи iPhone кабелем, перетащи `ScreenShare.ipa` в Sideloadly, введи Apple ID и нажми Start.
4. На iPhone открой Настройки → Основные → VPN и управление устройством и доверяй своему Apple ID.
5. На iOS 16 и новее включи Настройки → Конфиденциальность и безопасность → Режим разработчика. Телефон перезагрузится.
6. При первом запуске разреши доступ к локальной сети. Без этого телефоны не найдут друг друга.

С бесплатным Apple ID подпись действует 7 дней. После этого переустанови приложение через Sideloadly.

## Использование

1. Подключи телефон и телевизор к одной сети Wi-Fi.
2. Открой «Экран на ТВ» и нажми кнопку вещания → «Начать вещание».
3. Открой в браузере телевизора адрес из приложения, например `http://192.168.1.23:8080`.
4. На втором телефоне просто начни вещание. Его экран появится на телевизоре сам.

### Через Media Station X

Вместо браузера можно использовать приложение Media Station X из LG Content Store. Тогда адрес не нужно вводить при каждом запуске.

1. Начни вещание на iPhone.
2. В MSX открой Settings → Start Parameter → Setup и введи адрес телефона с портом, например `192.168.1.23:8080`. MSX загрузит `http://192.168.1.23:8080/msx/start.json`.
3. Теперь при каждом запуске MSX сразу открывает экран телефона. Кнопка «Назад» возвращает на страницу с кнопкой «Показать экран телефона».

Внутри MSX страница работает как видеоплагин. Пультом управляет MSX, поэтому кнопки «Во весь экран» там нет.

Стартовый параметр привязан к IP-адресу телефона. Чтобы адрес не менялся, закрепи его за телефоном в настройках роутера (резервирование DHCP). Если при запуске MSX вещание не идёт, приложение покажет ошибку загрузки.

### Если второй телефон не появляется

Если второй телефон не появляется, значит роутер не пропускает Bonjour. Добавь адрес второго телефона после `#`: `http://192.168.1.23:8080/#192.168.1.24:8080`.

Ещё одна причина: в гостевых сетях роутер часто изолирует клиентов друг от друга, и тогда телевизор не видит телефоны совсем.
